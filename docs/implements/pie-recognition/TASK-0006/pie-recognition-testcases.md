## 1. 正常系テストケース（基本的な動作）

### TC-001: computePhash - 同一ImageDataから同一ハッシュを返す

- **テスト名**: 同一ImageDataのpHash一致
  - **何をテストするか**: 同一のImageDataを2回computePhashに渡した場合に、同一のハッシュ値を返すこと
  - **期待される動作**: 決定的なアルゴリズムにより、同一入力は常に同一出力を生成する
- **入力値**: 32x32のRGBA ImageData（任意の固定パターン、例: 全ピクセルが同一色）
  - **入力データの意味**: 不変性（冪等性）を確認するための基本的な入力データ
- **期待される結果**: `hash1 === hash2`（2回の呼び出しで完全一致）
  - **期待結果の理由**: pHashアルゴリズムは決定的であり、同一入力に対して常に同一のハッシュを返す必要がある（tools/hasher版と同様の性質）
- **テストの目的**: computePhashの決定性・不変性の確認
  - **確認ポイント**: ハッシュ値が完全一致すること
- 🔵 tools/hasher/src/phash.test.ts「同一画像のpHashは一致する」と同等のテスト

### TC-002: computePhash - 16文字の16進数文字列を返す

- **テスト名**: pHashの出力形式が正しい
  - **何をテストするか**: computePhashの出力が16文字の16進数文字列（64bit）であること
  - **期待される動作**: DCT計算 → 8x8低周波 → 中央値比較 → 64bit → 16進数変換の結果が正しい形式
- **入力値**: 任意のRGBA ImageData
  - **入力データの意味**: 出力形式を検証するための一般的な入力
- **期待される結果**: `hash.length === 16` かつ `/^[0-9a-f]{16}$/` にマッチ
  - **期待結果の理由**: 64bit = 16ニブル = 16進数16文字。tools/hasher版と互換性のある形式
- **テストの目的**: 出力フォーマットの妥当性確認
  - **確認ポイント**: 長さ16文字、使用文字が0-9a-fのみ
- 🔵 tools/hasher/src/phash.test.ts「pHashは16文字の16進数文字列を返す」と同等

### TC-021: computePhash - DC成分（[0][0]）が常に0として扱われる

- **テスト名**: DC成分の除外確認
  - **境界値の意味**: DCTの[0][0]成分（DC成分）はハッシュの最初のビットを常に0にする設計
  - **境界値での動作保証**: 任意の入力画像でハッシュの最上位ビットが常に0であること
- **入力値**: 複数パターンのImageData（全黒、全白、チェッカーパターン等）
  - **境界値選択の根拠**: DC成分は画像全体の平均輝度を表し、明るさの異なる画像でも除外される
  - **実際の使用場面**: 照明条件の変化に対する耐性確保
- **期待される結果**: ハッシュの最上位4ビット（最初の16進数文字）が0-7の範囲（最上位ビットが0）
  - **境界での正確性**: `parseInt(hash[0], 16) <= 7`（最上位ビットが0）
  - **一貫した動作**: どのような入力でもDC成分ビットは0
- **テストの目的**: DCT処理でのDC成分除外の正確性確認
  - **堅牢性の確認**: アルゴリズムの正しい実装
- 🔵 tools/hasher/src/phash.ts のアルゴリズム「DC成分[0][0]を除く」「DC成分は常に0」に基づく
